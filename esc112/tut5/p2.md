### QuickSort using Hoare Partition Scheme with Recursion Tree Profiling

**Problem Statement:**
QuickSort is commonly implemented using **Hoare's Partition Scheme**, which typically performs about three times fewer swaps on average than Lomuto's scheme.

In Hoare's partition scheme:
- Uses the first element as pivot: `pivot = a[lo]`.
- Two indices $i$ and $j$ move inward toward each other from outside the subarray boundaries:
  - $i$ advances while $a[i] < \text{pivot}$.
  - $j$ retreats while $a[j] > \text{pivot}$.
  - If $i < j$, swap $a[i]$ and $a[j]$; otherwise, return boundary $j$.
- **Crucial difference**: Hoare partition does not guarantee that the pivot lands at index $j$. Therefore, the recursive call ranges are $[lo, p]$ and $[p + 1, hi]$ (not $p - 1$ and $p + 1$).

Write a C program that implements QuickSort with Hoare partition, traces each partition step, and profiles the recursion tree.

**Requirements:**
1. `int hoare_partition(int a[], int lo, int hi)`: Implements the two-pointer converging scheme described above, returning boundary index $j$.
2. `void quicksort_hoare(int a[], int lo, int hi, int depth, int n)`:
   - Prints each partition action: `Range [<lo>..<hi>] partitioned at j = <p>: <array_state>`.
   - Recursively sorts `[lo, p]` and `[p+1, hi]`.
   - Tracks `total_calls` and `max_depth` (the maximum call stack depth, starting with depth 1 for the initial call).
3. Count all element swaps performed.
4. Output: initial array, each partition step, the final sorted array, and the statistics line:
   `Total calls: <calls>, Max depth: <depth>, Total swaps: <swaps>`

**Input Format:**
- An integer $n$ ($1 \le n \le 100$).
- $n$ integers.
