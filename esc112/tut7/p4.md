### Relational CSV Sales Aggregator with Command-Line Arguments

**Problem Statement:**
In software engineering, business data is frequently split across multiple relational files. Processing such datasets requires reading files into structured memory records, joining them on unique keys, aggregating metrics, sorting results according to priority rules, and exporting summaries.

Write a command-line C program that processes product and sales records from two input CSV files and produces a sorted summary CSV report.

The program must be invoked from the shell as:
```bash
./s4 <products.csv> <sales.csv> <summary.csv> <min_revenue>
```

**Command-Line Validation & Error Handling:**
1. If `argc != 5`, print to `stderr`:
   `Usage: <argv[0]> <products.csv> <sales.csv> <summary.csv> <min_revenue>\n`
   and exit with status code `1`.
2. If the products file cannot be opened, print to `stderr`:
   `Cannot open products file\n`
   and exit with status code `1`.
3. If the sales file cannot be opened, print to `stderr`:
   `Cannot open sales file\n`
   and exit with status code `1`.
4. If the summary output file cannot be created, print to `stderr`:
   `Cannot create summary file\n`
   and exit with status code `1`.

**Input Files:**
1. **`products.csv`**: Contains up to 100 lines without a header. Each line has three comma-separated fields:
   `productID,category,price`
   - `productID`: Integer identifier (unique across products).
   - `category`: String (at most 31 characters, containing no commas or whitespace).
   - `price`: Positive integer unit price.
2. **`sales.csv`**: Contains up to 1000 lines without a header. Each line has two comma-separated fields:
   `productID,quantity`
   - A product may appear in multiple transactions.
   - If a transaction references a `productID` not present in `products.csv`, skip that transaction and increment the unknown transaction count.

**Computation & Filtering:**
1. For each valid transaction, look up the product's unit price and category.
   $\text{Transaction Revenue} = \text{unit\_price} \times \text{quantity}$.
2. For each category, compute:
   - Total units sold across all its products.
   - Total revenue generated.
   - Average quantity per transaction: $\frac{\text{Total Quantity}}{\text{Transaction Count}}$ formatted to 2 decimal places (`%.2f`).
3. Retain only those categories whose `TotalRevenue >= min_revenue`.

**Multi-Key Sorting Rules:**
Sort the retained categories using the following hierarchy:
1. **Primary Key:** `TotalRevenue` in **descending** order.
2. **Secondary Key (ties):** `TotalQuantity` in **descending** order.
3. **Tertiary Key (ties):** `Category` name in **alphabetical ascending** order (`strcmp`).

**Output Formats:**
1. **Output File (`summary.csv`)**:
   Include a header row followed by one row per qualifying category:
   ```csv
   Category,TotalQuantity,TotalRevenue,AvgQuantityPerTx
   <category>,<quantity>,<revenue>,<avg_qty>
   ```
2. **Standard Output (`stdout`)**:
   Print summary execution metrics:
   ```
   Products loaded: <np>
   Valid transactions: <nv>
   Unknown transactions skipped: <nu>
   Categories summarized: <nc>
   ```
