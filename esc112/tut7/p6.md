### Bit-Packed Binary Telemetry Archiver and Stream Filter

**Problem Statement:**
In embedded systems, internet-of-things (IoT) sensing networks, and network protocols, data records cannot be stored or transmitted as verbose text due to bandwidth and storage limitations. Instead, multiple fields of information are bit-packed into a single 32-bit unsigned integer and stored directly into binary files.

Implement a dual-mode C utility that encodes text telemetry readings into a bit-packed binary file using `fwrite`, and decodes/filters records from a binary file using `fread`, validating data integrity via an odd parity bit.

**Bit-Packing Specification (32-Bit Word):**
Each telemetry record is packed into one unsigned 32-bit integer (`unsigned int`):
- **Bits 0–6 (7 bits): `sensor_id`** ($0 \le \text{ID} \le 127$).
- **Bits 7–14 (8 bits): `temperature_raw`** ($0 \le T_{\text{raw}} \le 255$).
  Actual temperature $T \in [-40^\circ\text{C}, 87^\circ\text{C}]$ is stored as $T_{\text{raw}} = T + 40$.
- **Bits 15–21 (7 bits): `humidity`** ($0 \le H \le 100\%$).
- **Bits 22–27 (6 bits): `wind_speed`** ($0 \le W \le 63\text{ km/h}$).
- **Bits 28–29 (2 bits): `status`**:
  - `0`: `OK`
  - `1`: `WARNING`
  - `2`: `CRITICAL`
  - `3`: `OFFLINE`
- **Bit 30 (1 bit): `odd_parity`**:
  Set so that the total number of `1` bits across bits $0 \dots 30$ is **odd**.
- **Bit 31 (1 bit): Reserved** (must be 0).

**Program Modes & Invocations:**

1. **Encode Mode:**
   ```bash
   ./s6 encode <input_txt> <output_bin>
   ```
   - Input text file format (whitespace-separated fields per line):
     `<sensor_id> <temperature> <humidity> <wind_speed> <status_str>`
   - Packs each record and writes it to `<output_bin>` using binary stream output (`fwrite`).
   - Standard output:
     `Encoded <N> telemetry records into <output_bin>`

2. **Decode Mode:**
   ```bash
   ./s6 decode <input_bin> <min_temp>
   ```
   - Reads 32-bit records sequentially using binary stream input (`fread`).
   - For each record:
     - Check the parity across bits $0 \dots 30$. If the total number of set bits is even, print:
       `[CORRUPT RECORD at index <record_index>]`
       increment the corrupt count, and proceed to the next record.
     - Unpack the fields.
     - If the record satisfies $T \ge \text{min\_temp}$ **OR** `status == CRITICAL`, print:
       `[ID=<id>] Temp=<T>C Humidity=<H>% Wind=<W>km/h Status=<status_str>`
       and increment the flagged count.
   - Print final summary to `stdout`:
     `Total read: <total>, Corrupted: <corrupt>, Flagged: <flagged>`

**Error Handling:**
- Validate `argc` for both modes.
- If file opening fails (`fopen` returns `NULL`), print an error message to `stderr` and exit with status 1.

**Test Cases:**

* **Test Case 1 (Encode & Decode):**
* *Input File (`telemetry.txt`):*
```
1 25 60 12 OK
2 45 40 20 WARNING
3 18 85 5 CRITICAL
4 -10 90 25 OFFLINE
5 38 50 15 OK
```
* *Encode Invocation:*
  `./s6 encode telemetry.txt telemetry.bin`
* *Encode Output:*
```
Encoded 5 telemetry records into telemetry.bin
```
* *Decode Invocation:*
  `./s6 decode telemetry.bin 30`
* *Decode Output:*
```
[ID=2] Temp=45C Humidity=40% Wind=20km/h Status=WARNING
[ID=3] Temp=18C Humidity=85% Wind=5km/h Status=CRITICAL
[ID=5] Temp=38C Humidity=50% Wind=15km/h Status=OK
Total read: 5, Corrupted: 0, Flagged: 3
```

* **Test Case 2 (Corruption Detection):**
* *If the binary data of record index 1 has a bit flipped by transmission noise:*
* *Decode Invocation:*
  `./s6 decode telemetry_corrupted.bin 30`
* *Decode Output:*
```
[CORRUPT RECORD at index 1]
[ID=3] Temp=18C Humidity=85% Wind=5km/h Status=CRITICAL
[ID=5] Temp=38C Humidity=50% Wind=15km/h Status=OK
Total read: 5, Corrupted: 1, Flagged: 2
```
